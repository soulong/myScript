# Plan: Investigate NA values in flank ratio columns

## Observation

Columns `peak_gene_in_of_flank`, `peak_tss_in_of_flank`, `consensus_gene_in_of_flank`, and `consensus_tss_in_of_flank` contain many `NA` values.

## Root Cause

The `NA` values are actually `NaN` (R's representation of 0/0), which `is.na()` considers as `NA`. They arise from the ratio calculation:

```r
peak_gene_in_of_flank = peak_in_gene / peak_flank_gene
```

When **no sampled peaks overlap a gene** in a given bootstrap replicate:
- `peak_ig` is empty → `length(peak_ig) = 0`
- `peak_fg_cnt = cnt_pflank * 0 / n_peaks = 0` (denominator)
- `peak_in_gene_cnt = sum(cnt_peak[integer(0)]) = 0` (numerator)
- Result: `0 / 0 = NaN` → displayed/treated as `NA`

Same logic applies for TSS and consensus variants.

This is inherent to the bootstrap sampling: with `sample_size` often set to 0.4 (fraction of genes) converted to an integer count, a subset of peaks is randomly sampled each replicate. If that subset happens to contain no peaks overlapping genes or TSSs (possible when few peaks fall in those features), the ratio is undefined.

The issue existed in the **original code too** (per-peak flank sums also give 0 for an empty subset) — my flank consistency changes didn't introduce it.

## Proposed Approach

1. **Quantify the extent**: check what fraction of bootstrap replicates have `length(peak_ig) = 0` or `length(peak_it) = 0` to confirm the scenario.
2. **Decide on handling** the undefined ratios — options include:
   - Replace `NaN` with `NA` explicitly in post-processing (makes the undefined nature clear)
   - Use a pseudocount (`pmax(denominator, 1)`) to avoid division by zero
   - Replace with 0 (implies no enrichment, though mathematically different)
   - Filter out these replicates from summary statistics
